# yandex-skills

Три навыка (skills) для ИИ-агентов Claude Code и Codex, которые читают данные Яндекса через API, а не через веб-интерфейс:

| Навык | Что делает | Данные |
|---|---|---|
| `yandex-metrika` | отчёты Яндекс.Метрики, создание целей, проверка счётчика | поведение на сайте |
| `yandex-webmaster` | поисковые запросы, позиции, индексация, sitemap, переобход | видимость сайта в поиске |
| `yandex-wordstat` | спрос на запросы, похожие запросы, динамика | что ищут люди |

Скрипты написаны на Python 3 и используют только стандартную библиотеку. Установка зависимостей не нужна (см. `requirements.txt`).

Идея: агент должен управлять аналитикой программно. Вы задаёте вопрос обычным языком («откуда был трафик за месяц», «по каким запросам нас находят», «есть ли спрос на эту тему»), агент подбирает скрипт и параметры, запускает его и разбирает результат.

Цепочка данных целиком: Wordstat (что ищут) → Вебмастер (как сайт виден по этим запросам) → Метрика (кто пришёл и что сделал).

## Быстрый старт

```bash
git clone <URL-репозитория> yandex-skills
cd yandex-skills

# 1. Скопируйте шаблон настроек и впишите свои значения (файл .env в git не попадает)
cp .env.example .env
chmod 600 .env

# 2. Проверьте, что токен работает и найдите id своего счётчика
python3 yandex-metrika/scripts/metrika_check.py
```

Скрипты берут настройки из переменных окружения; если переменной нет, читают файл `.env` из текущей папки либо файл по пути из `YANDEX_ENV_FILE`. Для постоянной работы агента удобнее положить файл вне любого git-репозитория и указать путь в профиле оболочки:

```bash
mkdir -p ~/.config/yandex-skills
cp .env.example ~/.config/yandex-skills/.env
chmod 600 ~/.config/yandex-skills/.env
echo 'export YANDEX_ENV_FILE="$HOME/.config/yandex-skills/.env"' >> ~/.zshrc
```

## Переменные окружения

| Переменная | Нужна для | Описание |
|---|---|---|
| `YANDEX_OAUTH_TOKEN` | Метрика, Вебмастер | OAuth-токен Яндекса |
| `METRIKA_COUNTER_ID` | Метрика | id счётчика по умолчанию; можно несколько через запятую. Или флаг `--counter` |
| `WEBMASTER_HOST` | Вебмастер | сайт по умолчанию: домен `example.com`, URL или полный host_id `https:example.com:443`. Или флаг `--host` |
| `YANDEX_WORDSTAT_API_KEY` | Wordstat | API-ключ сервисного аккаунта Yandex Cloud |
| `YANDEX_WORDSTAT_FOLDER_ID` | Wordstat | идентификатор каталога Yandex Cloud |
| `YANDEX_ENV_FILE` | все | путь к файлу `KEY=VALUE` (по умолчанию `./.env`) |

Секреты (токен, API-ключ) не публикуйте, не вставляйте в чат и не коммитьте. Файл `.env` добавлен в `.gitignore`.

## Как получить доступ

Этот раздел собран по публичной документации Яндекса и по тому, что видно в скриптах. Пункты, которые не удалось проверить в репозитории, помечены.

### OAuth-токен для Метрики и Вебмастера

1. Откройте страницу создания приложения `https://oauth.yandex.ru/client/new` (не проверялось в репозитории; адрес из публичной документации Яндекс ID) и создайте приложение.
2. В правах доступа выберите:
   - Метрика: `metrika:read` (чтение отчётов) и, если нужно создавать цели, `metrika:write`. Эти права используют скрипты.
   - Вебмастер: нужно право на чтение данных о сайтах. По публичной документации это `webmaster:hostinfo`; `webmaster:verify` нужно только для добавления и подтверждения сайтов. Точные названия прав сверьте в документации Вебмастера.
   - В исходной рабочей установке один и тот же токен использовался и для Метрики, и для Вебмастера. Для токена с правами Метрики и Директа вызовы Вебмастера работали. Разумнее выдать приложению права Метрики и Вебмастера сразу.
3. Получите токен. Самый простой путь для личного использования – открыть в браузере адрес
   `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ID_ПРИЛОЖЕНИЯ>`
   и после подтверждения взять `access_token` из адресной строки (не проверялось в репозитории; исходная установка получала токен обменом кода авторизации).
4. Положите токен в `YANDEX_OAUTH_TOKEN`.

Срок жизни токена зависит от настроек приложения; в исходной установке он составлял около года. При ошибке HTTP 401 выпустите токен заново.

### Счётчик Метрики и сайт в Вебмастере

- Счётчик должен быть создан в Метрике на ваш аккаунт или вам выдан доступ. Список доступных счётчиков и их id покажет `python3 yandex-metrika/scripts/metrika_check.py`. Нужный id запишите в `METRIKA_COUNTER_ID`.
- Сайт должен быть добавлен и подтверждён в Яндекс.Вебмастере под тем же аккаунтом. Список сайтов покажет `python3 yandex-webmaster/scripts/webmaster.py hosts`. Нужный сайт запишите в `WEBMASTER_HOST`.
- Если подтверждаете сайт через DNS-запись, не удаляйте её потом: Яндекс периодически перепроверяет владение.

### Ключ для Wordstat (Yandex Cloud)

Wordstat работает через Yandex Cloud Search API (`https://searchapi.api.cloud.yandex.net/v2/wordstat`), отдельно от OAuth-токена.

1. Нужны аккаунт Yandex Cloud, платёжный аккаунт и каталог (folder). Идентификатор каталога – это `YANDEX_WORDSTAT_FOLDER_ID`.
2. Создайте сервисный аккаунт в этом каталоге и выпустите для него API-ключ. Значение ключа – `YANDEX_WORDSTAT_API_KEY`. Скрипт отправляет ключ заголовком `Authorization: Api-Key <ключ>` и `folderId` в теле запроса – это видно в коде.
3. Какую роль выдать сервисному аккаунту и какую область действия указать у ключа: сверьте с актуальной документацией Yandex Cloud Search API – в этом репозитории не проверялось.
4. Лимит API Wordstat – 100 запросов в час (см. раздел про Wordstat).

## Метрика (`yandex-metrika`)

### Как мы это используем

Метрика – основной счётчик для русскоязычной аудитории. Через навык агент отвечает на вопросы без открытия интерфейса:

- Сколько визитов и посетителей за период, динамика по дням.
- Откуда трафик: группировка по источникам (`ym:s:trafficSource`).
- Какие UTM-кампании приводят людей и сколько из них доходят до цели (`ym:s:UTMCampaign`, `ym:s:UTMSource` + метрики целей).
- Какие посадочные страницы получают трафик и как они удерживают (`ym:s:startURL` + отказы и длительность).
- Конверсии по целям (`ym:s:goal<ID>reaches`, `ym:s:goal<ID>conversionRate`).
- Исправен ли счётчик: `metrika_check.py` показывает счётчики и цели, а нулевой `total_rows` при валидном токене означает, что тег ещё не собирает данные или нет трафика.

Цели создаются тем же навыком: страница-«спасибо» (`--type url`) или JS-событие (`--type action`). Без `--commit` скрипт только печатает тело запроса, ничего не создавая.

### Примеры команд

```bash
# Проверить доступ, получить id счётчиков и целей
python3 yandex-metrika/scripts/metrika_check.py

# Визиты и отказы по источникам за 30 дней
python3 yandex-metrika/scripts/metrika_report.py --counter 12345678 \
    --dimensions ym:s:trafficSource --metrics ym:s:visits,ym:s:bounceRate \
    --date1 30daysAgo --sort=-ym:s:visits

# UTM-кампании
python3 yandex-metrika/scripts/metrika_report.py \
    --dimensions ym:s:UTMCampaign,ym:s:UTMSource --metrics ym:s:visits \
    --sort=-ym:s:visits --limit 50

# Посадочные страницы
python3 yandex-metrika/scripts/metrika_report.py \
    --dimensions ym:s:startURL --metrics ym:s:visits,ym:s:bounceRate,ym:s:avgVisitDurationSeconds \
    --sort=-ym:s:visits --limit 50

# Динамика по дням в JSON
python3 yandex-metrika/scripts/metrika_report.py \
    --dimensions ym:s:date --metrics ym:s:visits,ym:s:users --json

# Создать цель (сначала dry-run, затем с --commit)
python3 yandex-metrika/scripts/metrika_goal.py --name "Заявка" \
    --type url --match contain --url /thank-you
```

Если `METRIKA_COUNTER_ID` задан, `--counter` можно не указывать. Для убывающей сортировки пишите `--sort=-ym:s:visits` через знак равенства.

### Примеры запросов к агенту

- «Покажи, откуда был трафик на сайт за последние 30 дней, с долей отказов.»
- «Какие UTM-кампании за месяц привели больше всего визитов? Сколько из них дошли до цели с id 123456?»
- «Какие страницы чаще всего бывают первыми у посетителей, и где самые высокие отказы?»
- «Проверь, что счётчик работает и данные приходят: покажи счётчики и цели.»
- «Создай цель на страницу /thank-you. Сначала покажи, что отправится в API.»

## Вебмастер (`yandex-webmaster`)

### Как мы это используем

Вебмастер показывает видимость сайта в поиске Яндекса. Основные сценарии:

- Поисковые запросы: по каким запросам сайт показывается, сколько показов и кликов, средняя позиция.
- Резерв роста: запросы с большим числом показов и позицией примерно 4–15 – «почти в топе». Их подтягивают контентом. API по позиции не фильтрует, отбор делается на стороне агента.
- Индексация: сколько страниц в поиске и как менялось, ошибки обхода (`indexing`, `diagnostics`).
- Sitemap: список карт сайта и добавление новой (`sitemaps --add`).
- Переобход: отправка конкретного URL на переобход и контроль дневной квоты (`recrawl`).
- Общее здоровье: ИКС и число проблем по уровням важности (`summary`), технические проблемы сайта (`diagnostics`).

У только что добавленного сайта данные появляются не сразу: до загрузки хоста запросы `summary`, `queries`, `indexing` возвращают `HOST_NOT_LOADED`. Скрипт печатает понятное сообщение, это не ошибка конфигурации.

### Примеры команд

```bash
# Сайты аккаунта и статус подтверждения
python3 yandex-webmaster/scripts/webmaster.py hosts

# Топ запросов за 28 дней: показы, клики, средняя позиция
python3 yandex-webmaster/scripts/webmaster.py queries --host example.com \
    --indicator TOTAL_SHOWS --indicator TOTAL_CLICKS --indicator AVG_SHOW_POSITION \
    --days 28 --limit 50

# Сводка: ИКС, число проблем
python3 yandex-webmaster/scripts/webmaster.py summary --host example.com

# Проблемы сайта
python3 yandex-webmaster/scripts/webmaster.py diagnostics --host example.com

# Добавить sitemap
python3 yandex-webmaster/scripts/webmaster.py sitemaps --host example.com --add https://example.com/sitemap.xml

# Квота переобхода и отправка страницы на переобход
python3 yandex-webmaster/scripts/webmaster.py recrawl --host example.com --url https://example.com/page/
```

### Примеры запросов к агенту

- «По каким запросам нас находят в Яндексе за последние четыре недели? Дай таблицу и выдели, что докручивать.»
- «Найди запросы с большим числом показов и средней позицией от 4 до 15.»
- «Сколько страниц сайта в поиске и есть ли ошибки индексации или проблемы в диагностике?»
- «Добавь sitemap https://example.com/sitemap.xml и покажи, что он принят.»
- «Отправь на переобход страницу https://example.com/page/ и скажи, сколько квоты осталось.»

## Wordstat (`yandex-wordstat`)

### Как мы это используем

Wordstat – слой спроса при выборе темы. Тему или заголовок видео, а также запрос для статьи мы не придумываем, а проверяем по данным:

1. Для каждой кандидатной фразы (основная и близкие формулировки, а также ключевые фразы каждого варианта заголовка) отдельный вызов `top`: сколько показов в месяц и какие похожие запросы есть.
2. Динамика: месячная (с апреля текущего года до последнего полного месяца) и недельная (последние 12 полных недель).
3. Рост: среднее за последние 4 недели относительно среднего за первые 4 недели из последних 8, минус единица. Нулевой знаменатель или нехватка данных – рост неизвестен.
4. Пороги, которые мы применяем (рабочая политика, а не свойство API):
   - меньше 100 показов в месяц – фраза никогда не становится ядром заголовка;
   - меньше 500 в месяц – ядро не подходит, меняем фразу или подачу;
   - 500 и больше при росте от 25% за восемь недель – спрос подтверждён, от 50% – тема набирает обороты;
   - нет числа или динамики – проверка не пройдена.
5. Спрос – один из слоёв. Кроме него смотрят, что уже зашло у конкурентов, и что реально можно показать из собственного опыта. Всё без данных помечается как гипотеза.

Оговорки по данным: Wordstat запаздывает примерно на месяц, поэтому нужно сохранять фактически доступный последний период, а не предполагаемый сегодняшний.

Лимит API – 100 запросов в час. Поэтому исследование планируется пачками: сначала `top` по всем фразам списка, затем динамика только для тех, что прошли порог. На одну фразу уходит минимум три запроса (`top`, месячная и недельная динамика).

### Примеры команд

```bash
# Спрос и похожие запросы по нескольким фразам
python3 yandex-wordstat/scripts/wordstat.py top "claude code" "скиллы для claude" --num 30 --show 30

# Только Россия (225); Москва – 213
python3 yandex-wordstat/scripts/wordstat.py top --region 225 "claude code"

# Месячная динамика (конец периода – последний день месяца)
python3 yandex-wordstat/scripts/wordstat.py dynamics "claude code" \
    --period PERIOD_MONTHLY --from 2026-04-01 --to 2026-09-30

# Недельная динамика
python3 yandex-wordstat/scripts/wordstat.py dynamics "claude code" \
    --period PERIOD_WEEKLY --from 2026-08-03 --to 2026-10-25

# Сырой вызов (отладка)
python3 yandex-wordstat/scripts/wordstat.py raw top '{"phrase":"claude code","numPhrases":20}'
```

Операторы Wordstat (`!`, `+`, `[]`) в фразе не поддерживаются.

### Примеры запросов к агенту

- «Проверь спрос на фразы «монтаж видео ии», «ии для монтажа», «нейросеть для монтажа» и скажи, какая годится как ядро заголовка.»
- «У меня три варианта заголовка. Для ключевой фразы каждого проверь показы в месяц, и отбрось те, где меньше 100.»
- «Покажи недельную динамику по фразе и посчитай рост: последние четыре недели против первых четырёх из последних восьми.»
- «Составь список из 20 кандидатных запросов под статью и проверь их пачкой, уложившись в лимит 100 запросов в час.»

## Безопасность

- Токен и API-ключ хранятся только в переменных окружения или в файле вне репозитория с правами `600`. Не вставляйте их в чат с агентом.
- `metrika_goal.py` по умолчанию ничего не создаёт; запись происходит только с флагом `--commit`.
- Токену выдавайте минимум прав: для отчётов достаточно чтения.
- Команды `webmaster.py sitemaps --add` и `webmaster.py recrawl --url` меняют состояние в Вебмастере, поэтому просите агента показать команду перед запуском.

## Что не проверено

- Точные названия прав OAuth для Вебмастера и роль/область действия API-ключа Wordstat в Yandex Cloud (помечены в тексте).
- Порядок выпуска OAuth-токена по ссылкам из раздела «Как получить доступ» взят из публичной документации Яндекса и не прогонялся в этом репозитории.
- Часть имён группировок Метрики (география, устройства, даты) помечена в `yandex-metrika/references/metrika-api.md` как VERIFY-LIVE: проверьте живым запросом.
- Требования к датам недельной динамики Wordstat (например, начало периода с понедельника): сверьте с документацией API. В примерах использованы понедельник и воскресенье.
