# Яндекс.Метрика – отчёты и цели через API

Скилл читает данные счётчика Метрики и создаёт цели скриптами на Python 3 (только стандартная библиотека). Веб-интерфейс Метрики не нужен.

> Метрика отвечает на вопрос «что происходит на сайте» (визиты, источники, цели). Вопросы про поисковые запросы, позиции в выдаче и индексацию – это Вебмастер, скилл `yandex-webmaster`. Цепочка целиком: Вебмастер (видимость в поиске) → Метрика (визиты и поведение) → цель.

## Настройка

Переменные окружения (или файл `.env` в текущей папке, либо файл по пути из `YANDEX_ENV_FILE`):

| Переменная | Обязательна | Смысл |
|---|---|---|
| `YANDEX_OAUTH_TOKEN` | да | OAuth-токен; для чтения нужно право `metrika:read`, для создания целей – `metrika:write` |
| `METRIKA_COUNTER_ID` | нет | счётчик по умолчанию; можно несколько id через запятую. Вместо неё можно передавать `--counter` |
| `YANDEX_ENV_FILE` | нет | путь к файлу `KEY=VALUE` (по умолчанию `./.env`) |

Заголовок каждого запроса: `Authorization: OAuth <token>`. Токен не выводить в чат и не коммитить.

## Как пользоваться

Скрипты в `scripts/` сами подставляют токен, обрабатывают ошибки и квоты. Не собирайте API-запросы руками.

**1. Проверить доступ и найти id целей** – `scripts/metrika_check.py` (без аргументов): печатает счётчики токена и их цели. Запускать первым, если отчёт падает, или чтобы узнать `id` цели для метрик вида `ym:s:goal<ID>reaches`.

**2. Отчёт** – `scripts/metrika_report.py` (Stat API):
```bash
python3 scripts/metrika_report.py --counter <COUNTER_ID> \
    --dimensions ym:s:trafficSource --metrics ym:s:visits,ym:s:bounceRate \
    --date1 30daysAgo --sort=-ym:s:visits
```
Флаги: `--counter` (id или несколько через запятую; по умолчанию `METRIKA_COUNTER_ID`), `--metrics`, `--dimensions` (имена `ym:s:...` через запятую), `--date1`/`--date2` (`YYYY-MM-DD`, `NdaysAgo`, `today`), `--filters`, `--sort` (для убывания пишите через `=`: `--sort=-ym:s:visits`, иначе значение, начинающееся с `-`, воспринимается как флаг), `--limit`, `--accuracy`, `--json`. По умолчанию: последние 7 дней, метрики visits/users/pageviews/bounceRate.

**3. Создать цель** – `scripts/metrika_goal.py` (Management API, нужно право `metrika:write`). По умолчанию режим dry-run: печатает тело запроса и ничего не создаёт; для создания добавьте `--commit`.
```bash
# цель-страница (посетитель дошёл до /thank-you)
python3 scripts/metrika_goal.py --counter <COUNTER_ID> --name "Заявка" \
    --type url --match contain --url /thank-you --price 4990 --commit
# цель-событие (JS: ym(<id>, 'reachGoal', 'cta_click'))
python3 scripts/metrika_goal.py --counter <COUNTER_ID> --name "Клик по CTA" \
    --type action --url cta_click --commit
```
Поддержаны типы `url` (`--match exact|contain|start|regexp`) и `action` (`--url` = идентификатор JS-события).

## Какой отчёт выбрать

`references/metrika-api.md` – справочник «вопрос → параметры»: проверенные имена метрик и группировок, тела запросов для целей, Logs API, квоты. Имена в Метрике специфичны: `ym:s:bounceRate`, `ym:s:UTMCampaign`, посадочная страница – `ym:s:startURL` (не `landingPage`). Часть имён (география, устройства, даты) помечена в справочнике VERIFY-LIVE: проверьте живым запросом, прежде чем полагаться.

Типовые вопросы:
- откуда приходит трафик – `ym:s:trafficSource` (+ `ym:s:UTMSource`, `ym:s:UTMMedium`, `ym:s:UTMCampaign` для меток);
- куда попадают люди – `ym:s:startURL`;
- что конвертируется – `ym:s:goal<ID>reaches`, `ym:s:goal<ID>conversionRate`;
- динамика – группировка `ym:s:date`.

## Подводные камни
- `total_rows: 0` при валидном токене – счётчик ещё ничего не собрал или за период нет трафика; это не ошибка авторизации. `metrika_check.py` подтверждает доступ.
- Следите за `sampled`/`sample_share` в ответе; точность поднимается `--accuracy full` (значение по умолчанию в скрипте).
- Квоты: 30 запросов в секунду, 5000 в сутки, 3 параллельных; для отчётов лимит 200 запросов за 5 минут – при превышении HTTP 429.
- Ранние визиты из нерелевантных стран с нулевой вовлечённостью часто оказываются ботами предпросмотра – фильтруйте их.
- Для цели-события условие в теле запроса – `type: "exact"`, а не `"action"` (API отвечает 400).
