# Яндекс Wordstat – проверка спроса через API

Скилл отвечает на вопрос «ищут ли это люди и растёт ли интерес». Скрипт `scripts/wordstat.py` вызывает методы Wordstat в Yandex Cloud Search API (`topRequests`, `dynamics`) – Python 3, только стандартная библиотека (опционально `certifi`, если системные сертификаты не подходят).

## Настройка

| Переменная | Обязательна | Смысл |
|---|---|---|
| `YANDEX_WORDSTAT_API_KEY` | да | API-ключ сервисного аккаунта Yandex Cloud |
| `YANDEX_WORDSTAT_FOLDER_ID` | да | идентификатор каталога (folder) Yandex Cloud, он передаётся в теле каждого запроса как `folderId` |
| `YANDEX_ENV_FILE` | нет | путь к файлу `KEY=VALUE`; тот же файл можно задать флагом `--env` (по умолчанию `./.env`) |

Заголовок запроса: `Authorization: Api-Key <key>`. Это не тот OAuth-токен, что у Метрики и Вебмастера. Как получить ключ – в README. Ключ не выводить в чат и не коммитить.

## Команды

```bash
# Показы в месяц по фразам + самые частые похожие запросы
python3 scripts/wordstat.py top "claude code" "скиллы для claude" --num 30 --show 30
# Только по региону (225 – Россия, 213 – Москва)
python3 scripts/wordstat.py top --region 225 "claude code"
# Динамика по месяцам (дата конца периода – последний день месяца)
python3 scripts/wordstat.py dynamics "claude code" --period PERIOD_MONTHLY --from 2026-04-01 --to 2026-09-30
# Динамика по неделям
python3 scripts/wordstat.py dynamics "claude code" --period PERIOD_WEEKLY --from 2026-08-03 --to 2026-10-25
# Сырой вызов метода (отладка, нестандартные параметры, например regions в dynamics)
python3 scripts/wordstat.py raw dynamics '{"phrase":"claude code","period":"PERIOD_MONTHLY","fromDate":"2026-04-01T00:00:00Z","toDate":"2026-09-30T23:59:59Z","regions":["225"]}'
```

`top` печатает для каждой фразы число показов в месяц (`totalCount`), затем похожие запросы и ассоциации. `--json` добавляет сырой ответ. Ноль и отсутствие поля в обычном выводе выглядят одинаково (`?`): если число важно, смотрите сырой JSON.

Нюансы API (по документации): числа приходят строками (int64); для `PERIOD_MONTHLY` конец периода – последний день месяца; операторы `!`, `+`, `[]` в фразе не поддерживаются; данные запаздывают примерно на месяц–пять недель, поэтому не запрашивайте даты, которых ещё нет.

## Как мы используем: проверка спроса до выбора темы

Тема или заголовок берутся из данных, а не придумываются. Перед тем как предлагать заголовок видео или тему статьи:

1. Выпишите 1–3 фразы, которые человек ввёл бы в поиск, одну отметьте основной. Добавьте близкие формулировки.
2. Для каждой фразы – отдельный вызов `top`. Отсутствие фразы в списке похожих запросов не значит нулевой спрос: измеряйте каждую формулировку отдельно, особенно каждую ключевую фразу каждого варианта A/B заголовка.
3. Для основной фразы и близких вариантов – динамика по месяцам (с апреля текущего года до последнего полного месяца) и по неделям (последние 12 полных недель).
4. Рост считается так: среднее за последние 4 полные недели делится на среднее за первые 4 из последних 8 недель, минус 1. Нулевой знаменатель или отсутствие динамики – «рост неизвестен», а не бесконечный рост.
5. Решение по порогам:
   - основная фраза меньше 100 показов в месяц – никогда не ядро заголовка (допустима только как второстепенное слово);
   - меньше 500 в месяц – ядро не подходит, меняйте фразу или подачу;
   - от 500 в месяц и рост от 25% за восемь недель – спрос подтверждён; рост от 50% – тема «горячая»;
   - нет динамики или нет числа – проверка не пройдена, а не «условно хорошо».
6. Спрос – только один из слоёв. Остальные: упаковка (что уже взлетело у конкурентов) и собственный опыт автора. Всё, что не подкреплено данными, помечайте как гипотезу.

Пороги 100 / 500 / 25% – рабочая политика автора скилла, а не свойство API. Подстраивайте под свою нишу, но фиксируйте принятое значение.

## Лимиты и пакетная работа
- API Wordstat ограничен 100 запросами в час. Один вызов `top` на фразу и по вызову `dynamics` на месячную и недельную динамику – уже 3 запроса на фразу, поэтому исследование планируйте пачками: заранее составьте список фраз, сначала `top` по всем, затем динамику только для прошедших порог.
- Скрипт делает паузу 0,2 с между фразами внутри одного `top`, но часовой лимит сам не отслеживает. При HTTP 429 остановитесь и повторите после восстановления квоты; не подменяйте свежий результат старым без пометки.
- Сохраняйте сырые ответы с датой получения: цифры меняются, а старый отчёт не заменяет свежую проверку.

## Что запрещено
- Предлагать темы и заголовки «из головы», без чисел спроса.
- Суммировать показы пересекающихся широких запросов.
- Считать спрос по одной формулировке и переносить его на другую.
